# Z Browser

A custom Chromium-based web browser built with **Electron, TypeScript, HTML, and CSS**.

Z Browser is being developed from the ground up as a learning-focused browser project. The goal is not simply to produce a working browser, but to understand how a desktop browser application is structured, how Electron works, and how the different pieces of a browser fit together.

> **Project status:** Early development
> **Current stage:** Electron application shell and initial browser UI

---

## Overview

Z Browser is currently a minimal Electron application that creates a desktop window containing the initial browser interface.

The current interface includes:

* Back button
* Forward button
* Reload button
* Address/search input
* Dark browser-style toolbar

The browser interface is currently **visual only**. Navigation, web-page rendering, tabs, history, bookmarks, and other browser functionality have not yet been implemented.

## Current Architecture

The current application has two primary parts:

```text
Z Browser
│
├── Electron Main Process
│   └── main.ts
│
└── Browser UI
    └── index.html
```

### Main Process

`main.ts` is responsible for creating and managing the Electron application window.

It:

1. Imports Electron's `app` and `BrowserWindow` APIs.
2. Creates a `BrowserWindow`.
3. Configures the window's security-related web preferences.
4. Loads the browser UI from `index.html`.
5. Handles application activation.
6. Handles application shutdown behavior.

The current window is configured at `1400 × 900` pixels.

### Renderer UI

`index.html` currently contains the visible browser interface.

The interface consists of a toolbar containing:

```text
[ ← ] [ → ] [ ⟳ ] [ Search or enter address                 ]
```

The UI currently uses a dark theme with a `#202124` page background and `#292a2d` toolbar.

---

## Electron Configuration

Z Browser currently creates its `BrowserWindow` with:

```ts
webPreferences: {
    contextIsolation: true,
    nodeIntegration: false
}
```

This means Node.js APIs are not directly exposed to the renderer through `nodeIntegration`, while context isolation is enabled.

These settings are part of the project's initial security-conscious Electron configuration.

---

## TypeScript Configuration

TypeScript is configured with:

* Target: `ES2022`
* Module system: `CommonJS`
* Output directory: `dist`
* Root source directory: `src`
* Strict type checking enabled
* ES module interoperability enabled

These settings are defined in `tsconfig.json`.

## Running the Project

Install the project dependencies:

```bash
npm install
```

Build the TypeScript code:

```bash
npm run build
```

Start Z Browser:

```bash
npm start
```

The `start` script automatically builds the TypeScript project before launching Electron.

## Current Limitations

Z Browser is still at the beginning of development.

The following functionality is **not currently implemented**:

* Actual web-page navigation
* Address-bar navigation
* Search-engine integration
* Back/forward navigation logic
* Reload functionality
* Browser tabs
* Multiple windows
* Browser history
* Bookmarks
* Downloads
* Developer tools integration
* Browser settings
* Persistent browser data
* Custom search provider
* Browser extensions
* Advanced security architecture

The buttons and address field currently represent the intended browser interface but do not yet perform browser operations.

---

## Development Philosophy

Z Browser is being developed with two goals:

### 1. Build a Real Browser

The final application should provide the core functionality expected from a modern desktop browser while allowing us to control the architecture and user experience.

### 2. Understand What We Build

Every major feature will be accompanied by documentation explaining:

* What the feature does
* Why it is needed
* How it works
* Which Electron/Chromium concepts are involved
* How the code implements it
* What design decisions were made
* What trade-offs exist

The objective is to avoid treating the project as a collection of code generated by tools. The architecture should remain understandable and maintainable by the people building it.
